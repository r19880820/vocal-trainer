# UX Training

初心者向けUX設計・画面フロー・フィードバック文言の仕様。UI文言の正本([AGENTS.md](../AGENTS.md)参照)。

現時点では **Level 2「1音合わせ」(Playable MVP)** と **成長記録画面(Phase 7、§7)** を対象に定義する。Level 1/3/4 のUXは着手時に本ファイルへ追記する。

対象外: 実装コード、音声処理アルゴリズム(→ [AUDIO_ANALYSIS.md](AUDIO_ANALYSIS.md))、採点式・弱点判定ルールそのもの(→ [TRAINING_MODEL.md](TRAINING_MODEL.md))。本ファイルは「その結果をユーザーにどう見せるか」のみを扱う。

本ファイルの数値(色ゾーン境界・表示レンジ等)は以下に連動する仮値。変更時は両ファイルを同期させること(AGENTS.md「マジックナンバーはAUDIO_ANALYSIS.mdの値と同期させる」)。

| 項目 | 値 | 出典 |

| 「合っている」判定閾値 | \|cents\| ≤ 50 | AUDIO_ANALYSIS.md §5 pitchAccuracy/attackAccuracy |

## 1. UX原則

1. **対象は歌の初心者。専門用語は一切見せない。** cent / Hz / MIDI / confidence / YIN 等の語をユーザー向け画面(通常モード・詳細モードとも)に出さない。詳細モードで見せてよいのは「数値」であり「用語」ではない(§3.6)。
2. **感覚的な言葉に翻訳する。** 「-23 cents」ではなく「少し低いです ↑もう少し高く」。方向は矢印、程度は「少し/かなり」等の副詞で表す。
3. **結果画面の指摘は必ず1つだけ。** 複数の弱点が同時に低くても、primaryWeakness 以外は画面に出さない(TRAINING_MODEL.md の弱点判定ルールと一致させる)。
4. **詳細モードでのみ数値表示可。** 通常モードは常に感覚的表現のみ。詳細モードはオプトイン(結果画面の「詳しく見る」導線)。
5. **励まし基調。下手さを責めない。** 「失敗」「下手」「間違い」等の断定的なネガティブ語を使わない。できたことを先に言う。次の課題は「直すべき欠点」ではなく「次に伸ばす1点」として提示する。
6. **常に一緒に取り組む口調。** 命令形(「〜してください」)より提案形(「〜してみましょう」)。ユーザーを評価者・審判ではなく伴走者として扱う。
7. **視覚的にも緊張させない。** 赤色・警告アイコン・強い効果音/振動での「不正解」演出をしない(§5 アンチパターン)。

## 2. Level 2「1音合わせ」画面フロー

初回フロー: SC-1 → SC-2(初回のみ)→ SC-3(初回のみ)→ SC-4 → SC-5
2回目以降: SC-1 → SC-4 → SC-5(SC-2/SC-3はスキップ。声域は設定から変更可能という前提。§6参照)

### SC-1. ホーム/練習開始画面

- **目的**: アプリを開いたら迷わず「今日やること」に辿り着ける。
- **表示要素**:
  - アプリ名
  - 「今日の練習」カード1枚(Level 2 開始、または TrainingRecommendation が示す次の練習)
  - 直近の練習実績のごく簡易な表示(例:「これまで3回練習しました」程度。Progress Trackingの詳細画面はMVP対象外)
  - 開始ボタン
- **文言**:
  ```
  こんにちは。今日も声を出してみましょう。

  [ 今日の練習 ]
  音の高さを合わせる練習

  ▶ はじめる
  ```
- **操作**: 「はじめる」をタップ。
- **遷移**: 初回起動 → SC-2。マイク許可・声域設定が済んでいる → SC-4。

### SC-2. マイク許可・音量チェック(初回のみ)

- **目的**: OSのマイク許可を取得し、実際に声が拾えることを本人に確認させる。静かな環境の必要性を先に伝える。
- **表示要素**:
  - 案内テキスト(静かな場所の推奨)
  - マイク許可ボタン
  - 許可後: 音量メーター(バーやリング等。数値・dBは出さない)
  - 「声が届いています」の確認表示
- **文言**:
  ```
  はじめる前に

  まわりが静かな場所で練習すると、声を正しく拾えます。
  可能であれば、静かな部屋に移動してください。

  [ マイクを使えるようにする ]
  ```
  許可後:
  ```
  「んー」と声を出してみてください
  声が届いているか確認します

  (音量メーターが動く)

  声が届いています ✓
  [ つぎへ ]
  ```
  マイク拒否時:
  ```
  マイクが使えないと練習できません
  設定アプリからマイクを許可してください

  [ 設定を開く ]
  ```
  数秒たっても声が反応しない場合:
  ```
  まだ声が届いていないようです
  マイクに向かって、もう少し大きな声を出してみてください
  ```
- **操作**: 許可ダイアログ操作(OS)。発声して音量メーターの反応を目視確認 → 「つぎへ」。
- **遷移**: → SC-3。

### SC-3. 声域の簡易選択

- **目的**: 目標音の高さをおおまかにユーザーの声域へ合わせる(TRAINING_MODEL.md「開始時に低め/高めで簡易対応」)。
- **表示要素**: 2択カード(低め/高め)。あとから変更できる旨の一言。
- **文言**:
  ```
  ふだんの声に近いのはどちらですか?

  [ 低めの声 ]      [ 高めの声 ]

  あとから設定で変更できます
  ```
- **操作**: どちらかをタップして選択(即確定、確認ボタンなし)。
- **遷移**: → SC-4。選択結果は以後の目標音選定に使用する。

### SC-4. お手本再生 → 発声中のリアルタイム画面

- **目的**: お手本の音を聞き、同じ高さで発声しながら、その場でズレを把握できる。
- **表示要素**:
  - お手本再生インジケータ(スピーカーアイコン+再生中アニメーション)
  - **お手本の音名**(「お手本の音: ソ」。ドレミ表記、オクターブ表記なし — 2026-08-16 ユーザーフィードバック
    「何が難しいのか分からない」対策: どの音が苦手かを本人が識別・報告できるようにする)
  - リアルタイムピッチインジケータ(バー。詳細は §4)
  - 中央の「目標」マーカー+目標帯(±50cent相当のハイライト)
  - 状態テキスト(1行、動的に切り替わる)
  - 「もう一度お手本を聞く」ボタン
- **文言(状態別の1行テキスト)**:
  ```
  再生中:        お手本を聞いてください 🔊

  発声待ち:      同じ高さで「んー」と声を出してみましょう

  合っている:    合っています ◎

  少し低い:      少し低いです ↑もう少し高く
  少し高い:      少し高いです ↓もう少し低く

  かなり低い:    低いです ↑もっと高く
  かなり高い:    高いです ↓もっと低く

  声が届かない:  聞こえていません
  ```
- **操作**: 画面表示と同時にお手本を自動再生。再生後、自動的に発声待ち→計測開始(タップ操作不要)。「もう一度お手本を聞く」は任意操作。
- **遷移**: 発声が一定時間成立、または無音が続いて区切りがついたら自動的に SC-5 へ(継続時間・終了条件の厳密な定義は §6 未確定事項)。

### SC-5. 結果画面

- **目的**: できたことを1つ褒め、次に直すことを1つだけ示し、次の行動(もう一回/次の練習)へ迷わず進める。
- **表示要素**:
  - シンプルな肯定的ビジュアル(点数の大きな数字は出さない。チェックマーク等の控えめな表現)
  - 褒め文(1文)
  - 次に直すこと(1文、見出し的に)
  - 具体的な行動の提案(1文)
  - ボタン:「もう一回」「次の練習へ」
  - (任意)「詳しく見る」リンク → 詳細モード(§3.6)
- **文言テンプレート**(具体は §3):
  ```
  {褒め文}

  次は「{次に直すこと}」を練習しましょう
  {具体的な行動}

  [ もう一回 ]   [ 次の練習へ ]

  詳しく見る >
  ```
- **操作**: 「もう一回」→ SC-4 の発声待ちへ戻る(同じ目標音)。「次の練習へ」→ TrainingRecommendation が示す次のExerciseへ(弱点別、TRAINING_MODEL.md参照)。
- **遷移**: 上記いずれかのボタン操作で次画面へ。

## 3. フィードバック文言集

### 3.1 褒めポイントの選定ルール

primaryWeakness(TRAINING_MODEL.mdの弱点判定ルールで決まる)以外の指標のうち、**もっとも値が高いもの**を褒める。

- 褒め対象の値が 0.7 以上 → その内容を具体的に褒める(§3.2〜3.4のパターンを使用)
- 全指標が 0.7 未満(褒められる材料がない)→ スキルではなく「取り組んだこと自体」を褒める汎用文言にフォールバック
  ```
  最後まで声を出し切りましたね。
  ```
- 褒め対象の値の高さで強度の言い換えを変える:
  - 0.85以上: 「とても」「しっかり」
  - 0.7〜0.85: 「かなり」「けっこう」

### 3.2 primaryWeakness = pitchAccuracy(音の高さが合っていない)

```
{褒め文(安定して声を出せている/入りが良い 等、§3.1のルールで選定)}

次は「音の高さ」を練習しましょう
お手本をよく聞いてから、同じ高さになるように意識して声を伸ばしてみましょう
```

### 3.2b 方向付きアドバイス(pitchAccuracy でズレの方向が一貫している場合)

符号付きズレ中央値が ±ZONE_NEAR_CENTS(100)を超えて一方向のとき、§3.2 の行動文を方向付きに差し替える
(octaveOff≠0 の回は除く):
```
低め傾向: お手本より低くなりやすいようです。思っているより少し高めをねらって声を出してみましょう
高め傾向: お手本より高くなりやすいようです。思っているより少し低めをねらって声を出してみましょう
```

### 3.3 primaryWeakness = pitchStability(声が安定していない)

```
{褒め文(高さは合っている/入りが良い 等)}

次は「声の安定」を練習しましょう
音を出したら、揺れないように一定の高さのままキープしてみましょう
```

### 3.4 primaryWeakness = attackAccuracy(音の入りが遅い/ズレる)

```
{褒め文(高さは合っている/安定して伸ばせている 等)}

次は「音の入り」を練習しましょう
最初から目標の高さを頭の中でイメージしてから、パッと声を出してみましょう
```

参考(TRAINING_MODEL.md記載の例文はこのパターンの詳細モード版):
```
音の高さはかなり合っています。

次は「音の入り」を練習しましょう。
最初の音に入るまで約0.8秒かかっています。
```
通常モードでは秒数を出さない。時間の数値表示は詳細モードのみ(§3.6)。

### 3.5 測定不能(声が小さい / 短すぎる)

primaryWeaknessを判定せず、測定不能として扱う(TRAINING_MODEL.md「測定有効性チェック」)。褒め+次の1点+行動の型は維持しつつ、対象はスキルではなく「発声のしかた」にする。

**声が小さい・聞き取れない場合(confidenceゲート等で無声扱い)**:
```
声を出そうとしてくれてありがとうございます。

次は「声の大きさ」を意識してみましょう
マイクに向かって、もう少しはっきり「んー」と声を出してみてください
```

**声を出す時間が短すぎる場合(発声開始条件=連続150ms以上が成立しない等)**:
```
声を出そうとしてくれてありがとうございます。

次は「声を伸ばす長さ」を意識してみましょう
一度出した声を、3秒くらい伸ばしたままキープしてみましょう
```

**原因を区別できない場合の汎用文言**(§6参照。実装側で「小さい/短い」を判別できない場合はこちらを使う):
```
声をうまく聞き取れませんでした。

次は「声の届け方」を意識してみましょう
マイクの近くで、はっきり・長めに「んー」と声を出してみましょう
```

### 3.5b オクターブ違い(octaveOff = ±1)

高さの「感覚」は合っているのに1オクターブ上/下で歌っているケース。初心者の最頻出パターンであり、**弱点判定より優先して**この専用文言を出す(TRAINING_MODEL.md)。オクターブ違いは能力不足ではなく「どの高さで出すか」の選択の問題なので、明確にポジティブに扱う。

**1オクターブ低い場合**:
```
音の高さの感覚はしっかり合っています。

次は「声の高さの位置」を合わせてみましょう
いまはお手本よりひとまわり低い声で歌えています。
次はあなたの声に合わせた高さのお手本で練習しましょう(慣れてきたら少しずつ上げていきます)
```
(1オクターブ高い場合は「ひとまわり高い声で〜少しずつ下げていきます」に反転)

**裁定(2026-08-16 レビューC-5)**: 「もう少し高い声で出しましょう」という指示は、目標音がユーザーの
音域外で物理的に不可能な場合があるため**使わない**。提案(次の練習)と文言の両方を
「お手本をユーザーの声の高さに寄せる」方向へ統一する(TRAINING_MODEL.md の提案表と一致)。

「オクターブ」という語は詳細モードでのみ使用可。通常モードは「ひとまわり低い/高い」。
なお、この提案で起動される次の練習は目標音をユーザーの発声側に寄せたもの(TRAINING_MODEL.md)。

### 3.5c 目標未到達(一度も目標の高さに届かなかった場合)

pitchAccuracyがほぼ0で、attack/stabilityが測定不能のケース。**「素早く」「安定して」等の助言は絶対に出さない**(まだその段階ではない)。「まず目標音に到達すること」だけを伝え、易しくした練習(音域を下げたLevel 2 / Level 1)へ誘導する。

```
最後まで声を出し切りましたね。

次は「音を探す」練習をしてみましょう
声の高さを下から上へゆっくり変えながら、
お手本と同じ高さを探してみましょう。
もう少し出しやすい高さのお手本から始めます
```

### 3.5d すべて上級バンドの場合(弱点なし)

全指標が上級バンドのときは弱点をでっち上げない。褒め+次の挑戦のみ:
```
すべてとても良くできています!

次は「つぎの音」に挑戦しましょう
この調子で、少し違う高さの音でも試してみましょう
```

### 3.6 数値表示ルール(詳細モードのみ)

- 通常モードでは cent 等の数値を一切出さない。
- 詳細モードでは **cent の実測値をそのまま数値表示してよい**が、以下は禁止する:
  - 「半音の何分の一」のような音楽理論換算表現(かえって初心者には難解)
  - 「cent」というラベル自体をそのまま出すこと(内部単位名は非表示。感覚語+数値の併記にする)
- 表示形式の例:
  ```
  少し低いです(あと少しで合う: -23)
  ```
  のように、感覚語を主、数値を補助として括弧書きで添える。単位記号は出さない。
- attackAccuracy の時間(秒)は詳細モードでは「0.8秒」のように単位付きでそのまま表示してよい(TRAINING_MODEL.md記載例と一致。秒は日常語のため許可)。
- 詳細モードの先頭に「お手本の音: ソ」と「傾向: お手本より低め(-180)」を表示する
  (傾向ラベルは ±30 で「ちょうど」、それ以外は低め/高め。数値は符号付きズレ中央値、単位表記なし)。

## 4. リアルタイムインジケータ仕様(SC-4)

### 4.1 表示レンジとマッピング

- 表示レンジ: **±200 cent**(バー全幅)。半音=100centなので、上下2半音まで視認できる。
- 0 cent(目標音)を画面中央に固定。ユーザーの現在値(EMA平滑後の cents)をバー上の水平位置へ線形マッピングする。
- ±200centを超える差は**バー端に張り付かせて**表示する(実際の値をそのまま外挿しない。「振り切れている」ことだけ分かればよい)。

### 4.2 ゾーンと色

| ゾーン | 範囲 | 色の方針 | 状態テキスト例 |
|---|---|---|---|
| 合っている | \|cents\| ≤ 50 | 緑(達成色) | 「合っています ◎」 |
| 近い | 50 < \|cents\| ≤ 100 | 黄〜琥珀(注意色ではなく"あと少し"色) | 「少し低いです ↑もう少し高く」 |
| 遠い | 100 < \|cents\| ≤ 200(clamp) | 落ち着いた青灰色(警告色にしない) | 「低いです ↑もっと高く」 |
| 声未検出 | voicing ≠ voiced | ドットは輪郭のみに減光。色は使わない | 「聞こえていません」 |

**赤は使用しない**(§5 アンチパターン)。「遠い」ゾーンも失敗色ではなく中立色にとどめる。

閾値50centはAUDIO_ANALYSIS.mdのpitchAccuracy判定基準(±50cent)と一致させてある。100centの境界はUX側の追加区分(仮値、実データで調整可能)。

### 4.3 目標帯の表現

- 中央に固定マーカー(縦線+「目標」ラベル)。
- その左右 ±50cent 幅を薄い緑のハイライト帯として常時表示し、「ここに入れば合っている」を視覚的に伝える(数値のcentは出さない)。
- ユーザーの現在位置は帯の上を移動する丸(●)。

```
低い                          高い
────────░░░●░░░────────
             ▲
            目標
```
(░░░ = ±50cent の目標帯、● = ユーザーの現在位置)

### 4.4 更新頻度・アニメーション

- 値の更新元は表示用smoothing後(EMA α≈0.3)の cents。ホップ長16ms(約62.5Hz)ごとに新しい値が来るので、画面もそのペースで追従してよい。
- ドットの移動は急なジャンプにならないよう、100ms程度のイージングで滑らかに補間する。
- 状態テキスト(ゾーン名)の切り替えは**ヒステリシスを設ける**(境界付近で細かく点滅しないよう、新しいゾーンに150ms以上留まってからテキストを切り替える)。境界上でのバタつきは「不安定である」という誤ったプレッシャーを与えるため避ける。
- 目標ゾーンに入った瞬間は、軽いグロー/パルス程度の祝う演出のみ(強い効果音・振動は使わない)。
- 声未検出への切り替えは200〜300msかけてフェードし、瞬時に消えて驚かせない。

### 4.5 声が検出できない時の表示

- 発声フェーズ開始前(まだ一度も声が届いていない): ドットは中央付近に薄く表示、テキストは「同じ高さで『んー』と声を出してみましょう」。
- 発声中に一時的に無声(silence gate/confidenceゲート不通過)が続いた場合: ドットをフェードアウトし輪郭のみに、テキストを「聞こえていません」に切り替える。数秒経っても声が戻らない場合は「もう少し大きな声で」の一言を添えてもよい。
- オクターブ誤検出等による瞬間的な外れ値は処理層(AUDIO_ANALYSIS.md §3)で補正済みの値を前提とするため、UI側で追加のクランプ処理は不要(ただし表示クランプ±200centは適用する)。

## 5. アンチパターン(やってはいけない表示)

- **点数の大きな数字表示で締めない。** 「78点」のような総合スコアを結果画面の主役にしない。褒め文+次の1点が主役。
- **結果画面で複数の指摘を並べない。** primaryWeakness以外の弱点が低くても、通常モードでは触れない(詳細モードでのみ内訳を出してよい)。
- **赤字・警告色での失敗表示をしない。** リアルタイムインジケータ・結果画面とも、赤やバツ印による「不正解」表現を使わない。
- **「失敗」「下手」「間違い」等の断定的ネガティブ語を使わない。** 常に「次に伸ばす1点」というポジティブな枠組みで表現する。
- **専門用語(cent/Hz/MIDI/confidence/YIN等)をそのまま出さない。** 詳細モードでも単位・用語のラベルは出さず、数値のみ添える(§3.6)。
- **強い効果音・振動での「不正解」演出をしない。** 目標達成時のポジティブな演出は軽めに留め、未達成時に何かを鳴らす/震わせることはしない。
- **インジケータをカクカク動かさない。** 平滑化・イージングなしの生値直結表示は、実際には合っていても不安定に見えて不安を煽る。
- **命令口調にしない。** 「もう一度やり直してください」ではなく「もう一回」「次はこうしてみましょう」のような提案・伴走の口調にする。
- **進捗低下を責めない。** 週次等の推移表示(将来画面)で数値が下がっても、後退を指摘する文言にしない。停滞・後退時こそ励ましを優先する(本ファイルはLevel2 MVP対象のため詳細は将来追記)。
- **測定不能を「失敗」として見せない。** 声が小さい/短いは技術的な検出限界であり、ユーザーの歌唱力の否定ではない。褒め+行動提案の型を崩さない(§3.5)。

## 7. 成長記録画面(Phase 7)

対象: `src/ui/ProgressScreen.tsx`。ホームの「せいちょうを見る」から遷移し、「← もどる」でホームへ戻る。
週次集計ロジックは `src/core/progress/aggregate.ts`(純TS)、永続化は `src/data/progressStore.ts`
(ADR-004)。**本節は §1 UX原則・§5 アンチパターンの適用範囲であり、内容は矛盾しない**
(専門用語なし・数値の見せ方は§3.6準拠・進捗低下を責めない=§5「進捗低下を責めない」の実装がこの画面)。

### 7.1 表示要素

- 見出し「せいちょう」
- 「これまで {N} 回練習しました」(N = practiceCount。validity=ok の練習のみを数える。ホーム画面の
  簡易表示 SC-1 と同じ数値・同じ文言を使い、画面間で数字の意味がぶれないようにする)
- スキルごとのカード(データがある指標のみ表示。無い指標は行ごと出さない — §1.6「一緒に取り組む」、
  無理に埋めない):
  | skillId | ラベル | 表示形式 | 備考 |
  |---|---|---|---|
  | pitchAccuracy | 音の高さ | `{value*100を四捨五入}%` | 高いほど良い |
  | medianAbsCents | ズレの平均 | `{valueを四捨五入}`(単位記号なし) | ラベル下に常時「数値が小さいほど、目標の高さに近いです」を添える(§3.6: cent という語は出さない)。**小さいほど良い** |
  | pitchStability | 声の安定 | `{value*100を四捨五入}%` | 高いほど良い |
  | attackAccuracy | 音の入り | `{value*100を四捨五入}%` | 高いほど良い |
  | directionAccuracy | 音の上下 | `{value*100を四捨五入}%` | 高いほど良い(Level 1 セット結果。2026-08-16 Phase 6追加) |
  各カード: 「今週 {値}」+ (前週データがあれば)「{↗/→/↘} 先週 {値}」

### 7.2 変化表示と低下時の文言

- 週次比較(直近週 vs 前週)の結果を矢印1文字で示す: ↗ 改善 / → 横ばい / ↘ 低下
- 色は使わない(赤・警告色なし。§5「赤字・警告色での失敗表示をしない」を継承)
- **低下時(↘)も責めない**: 数値の下に必ず一言を添える
  ```
  調子には波があります。続けていきましょう
  ```
  「下がった」「悪化」等の否定語は使わない。停滞・後退時こそ励ましを優先する(§5「進捗低下を責めない」)

### 7.3 空状態・データ不足時の文言

- **練習実績が0回(practiceCount=0)**: スキルカードを一切出さず、
  ```
  練習するとここに成長が表示されます
  ```
  のみを表示する(「データが無い」を失敗として見せない。§5「測定不能を『失敗』として見せない」と同じ考え方)
- **その指標が1週分しかない(前週データなし)**: 矢印による比較は出さず、今週の値のみを表示し
  ```
  練習を続けると、ここに先週との変化が表示されます
  ```
  を添える。「比較できない」ことを欠落として見せない
- pitchStability / attackAccuracy はそもそも null になり得る指標のため、該当週のデータが1件もなければ
  そのスキル行自体を表示しない(「測定できず」を毎回出して不安がらせない)

### 7.4 集計ルール(内部・非表示)

- 週の単位は ISO 8601 週(月曜始まり)。週番号自体はユーザーに見せない(§1「専門用語を出さない」と
  同じ理由 — 内部の日付計算ラベルであってユーザー向け語彙ではない)
- **paramsVersion が現行と異なる SkillSnapshot は集計から除外する**(較正で数値の意味が変わるため。
  ADR-004 / ARCHITECTURE.md 依存ルール「バージョン跨ぎ比較禁止」)。旧バージョンのデータは
  黙って比較対象外になる(エラー表示はしない)
- 直近8週まで保持。それ以前のデータは画面には出さないが、ストレージ(`vt.progress.v1`)からは削除しない
