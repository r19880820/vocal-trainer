# ADR-001: Pitch Detection 方式

- Status: **Accepted**(2026-08-16 Opusレビューの条件5点を反映済み)
- Date: 2026-08-16
- Decider: Fable(起案・統合)/ Opus(レビュー)

## Context

マイク入力からリアルタイムで F0(Hz)・Note・cent・confidence を取得する。
要件: スマホでのリアルタイム性(更新~86Hz・表示遅延≤100ms)、歌声(MVPは80〜700Hz)での精度±10cent、
低CPU負荷、ライセンス上の自由、実装の理解容易性(自前実装・チューニング前提)。

## 検討した選択肢

| 方式 | 精度 | CPU | リアルタイム | 備考 |
|---|---|---|---|---|
| **YIN** | 高(単声) | 低〜中 | ◎ | 実装が単純明快。CMNDFから信頼度が得られる。参考実装・解説が最多。オクターブエラーは後処理+診断で対応 |
| pYIN | 最高(単声) | 中〜高 | △ | HMM/Viterbi平滑化で頑健だが実装複雑・遅延増。系列全体への処理であり「1フレーム→1サンプル」の枠に嵌まらない |
| MPM (McLeod) | 高 | 低〜中 | ◎ | YINと同等クラス。NSDFベース。チューナー系で実績(TarsosDSP等) |
| 素朴な自己相関 | 中 | 低 | ◎ | オクターブエラー多発。歌声には不足 |
| CREPE等 NN系 | 最高 | 高 | △ | モデル同梱・推論基盤が必要。「決定論的アルゴリズム優先」の方針に照らしMVPでは過剰 |

## Decision

**YIN を自前実装で採用。** 主要パラメータ(正本は AUDIO_ANALYSIS.md):

- 内部レート = 実キャプチャレート ÷ 2(22.05k/24kHz)。**16kHzは不採用** — τ量子化が440Hzで47cent幅となり±10cent目標が原理的に未達(レビューC-2)
- 探索範囲 80〜700Hz(MVPターゲットC3〜A4+余裕。上限拡大はVocal Range測定と同時)
- 積分窓 W=1024、バッファ N=W+τ_max(WとNを区別。不変条件 W≥2·τ_max)
- 絶対閾値0.15: 閾値を下回る最初のτを採用、無ければ大域最小+`belowThreshold=false`(YIN原典準拠)。voicing判定は belowThreshold に一本化し、confidence への第二閾値は置かない(レビューC-4)
- 放物線補間はτドメイン。confidence = clamp(1−CMNDF(τ̂), 0, 1)
- `PitchDetector` は**状態を持つストリーム型interface**(reset/push/flush)— pYINのViterbi窓も同一契約に収まり、差し替えが実在する逃げ道になる(レビューC-8)

YIN を MPM より優先する理由: アルゴリズムの解説・参考実装が最も豊富で、複数AI開発体制での
実装レビュー・検証がしやすい。性能差は処理層で吸収できる。

## Consequences

- (+) 依存ライブラリゼロ。純 Dart で単体テスト可能。ライセンス問題なし
- (+) CPU ~20M MAC/s(Dart AOTで1コア数%)。FFI/C への移行は実測で必要になった場合のみ
- (−) ささやき声・強い息漏れに弱い → voicing=unclear として検出し理由別UX文言(誤数値を出さない)
- (−) 単発オクターブエラーは処理層で補正するが、**持続的オクターブ差は補正せず診断(octaveOff)として扱う**(補正で消すと最重要の初心者診断が消える — レビューC-5)
- (−) pYIN移行は interface 契約上は差し替え可能だが、閾値・confidence分布の再較正が必要(コストを過小評価しない)

## 検証方法(Phase 1 PoC の合格条件)

1. **F0スイープ(80〜700Hz)のバイアス曲線**を測定し、全帯域で誤差±10cent以内(単一周波数の一点測定は非識別的なので不可)。合成波形はサイン波・倍音付き・ノイズ混入の3種
2. スループット: 処理時間 < ホップ11.6ms
3. **レイテンシ(スループットとは別物)**: ループバック実測(クリック再生→自機録音→検出時刻差)で表示遅延≤100msの予算内
4. 起動時セルフテスト(440Hz再生→録音→440±20Hz)が実機で合格(実レート契約の検証)
